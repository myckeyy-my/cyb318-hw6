Date: 11.17.2026

Goal:
- Day 2 milestone — implement lap timing and a five-attempt qualifying system.
- Integrate an F1 car image and implement front-wheel steering.
- Improve track boundaries with gravel runoff areas, white boundary lines, hard barriers, and red-and-white corner kerbs.

Prompt:
- Requested a JavaScript-based implementation guided by the project PRD and optimized for GitHub Pages compatibility.
- Requested improvements to track boundaries:
  - Replace the existing hard track boundaries with white boundary lines.
  - Add gravel runoff areas between the asphalt and outer hard barriers.
  - Slow the car down when driving on gravel.
  - Invalidate a lap only when all four wheels cross the white boundary lines.
  - Automatically generate red-and-white striped kerbs at corners as the default track design.

AI Implemented:
- Updated track.js and renderer.js; created qualifying.js and lap-detection.js.
- Implemented start/finish line detection using world coordinates, including directional crossing validation and rearming.
- Implemented lap timing, valid/invalid lap tracking, and fastest valid lap recording.
- Added a five-attempt qualifying limit and benchmark-based success/failure evaluation.
- Implemented lap invalidation upon wall or static obstacle collisions.
- Added a qualifying HUD and session restart functionality using a button or the R key.
- Implemented session restart functionality that resets the car, camera, timer, lap detector, and session counters.
- Generated asphalt boundary lines, gravel runoff strips, and hard barriers based on the track centerline.
- Added gravel drag and reduced acceleration when the car drives outside the asphalt.
- Implemented four-wheel position tracking and track-limit validation.
- Automatically generated red-and-white kerb stripes along curved track sections.
- Created reusable default boundary dimensions with optional track-specific configurations.
- Integrated the F1 car image and separate front-wheel sprites with adjustable steering angles.

Tested:
- Start/finish line direction detection, rearming, stationary crossing rejection, lap timing, and lap recording.
- Collision invalidation, duplicate collision prevention, fastest-lap tracking, and benchmark evaluation.
- Five-attempt enforcement and session restart functionality.
- Browser game-loop integration, including lap initiation, obstacle collision, and session restoration.
- Game page, HUD, and restart button rendering through a local HTTP server.
- Keyboard acceleration and restart behavior.
- Track geometry, including asphalt boundaries, gravel runoff, corner kerbs, and hard barriers.
- Four-wheel boundary detection with zero, one, two, three, and four wheels outside the asphalt.
- Gravel acceleration and recovery behavior when returning to asphalt.
- Outer-barrier collision and non-colliding gravel runoff.
- Kerb contact without invalidating the lap.
- Car image loading and rendering.
- Separate wheel sprites and different left/right steering angles.

Worked:
- Gravel runoff areas and their speed-reduction mechanics worked.
- Lap timer successfully started and stopped, recorded the fastest valid lap, and displayed success or failure.
- Restart button worked correctly.
- Lap validation correctly invalidated attempts when all four wheels crossed the track boundary.
- Lap timer and session data reset appropriately.

Failed:
- The gravel initially slowed the car so much that it became impossible to drive out of it. This issue was subsequently fixed.
- The lap detection system initially recorded a lap when the car reversed direction and crossed the finish line again. This was identified as a validation issue.

Changed:
- Replaced the original hard track boundaries with non-colliding boundary lines and added gravel between the asphalt and outer hard barriers to improve navigation.
- Changed track-limit validation so that a lap is invalidated only when all four wheels are outside the asphalt, rather than immediately when the car touches the boundary.

Learned:
- There are a lot of things that we must specifically mention so that the AI understand what to do
- We should only develop one thing at a time to maximize accurate response from the AI

Date: 11.20.2026

Goal:
- Add a distinct fictional racing circuit for each championship level.

AI Implemented:
- Added spline-based centerline track generation while retaining the original rounded-rectangle prototype.
- Created three circuits: Apex GP, Harbor Street, and Velocity GP.
- Standardized asphalt width to 16 units across all three circuits.
- Redesigned Harbor Street to maintain sufficient clearance between adjacent road sections, runoff areas, and barriers.
- Redesigned Velocity GP with long straights and four tighter rounded corners.
- Added configurable rectangular centerline dimensions to independently control horizontal and vertical straights.
- Updated championship track selection to load the appropriate circuit for each level.
- Updated the HUD to display the track name and revised project documentation.

Tested:
- Browser loading of all three circuits.
- Consistent asphalt width, closed track geometry, and start/finish line crossings.
- Centerline and asphalt boundary intersections across all circuits.
- Harbor Street runoff and barrier geometry, confirming no self-intersections and sufficient clearance between non-adjacent track sections.
- Level 3 geometry, confirming no barrier/asphalt intersections or track self-crossings.
- Level transitions, benchmark selection, session resets, and Level 3 victory.
- Automatic success and failure evaluation after five attempts.
- Browser rendering performance for generated kerbs and track geometry.

Failed:
- The outer border interfered with the racing track and created blockages.
- There are a lot of bugs when the AI try to generate a new track where in the car might be completely boxed.

Learned:
- Iteration makes the AI more efficient rather than trying to get a thing right using a long prompt
- Giving the AI examples helps it creates a baseline of expected outcomes
